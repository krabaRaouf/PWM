# PWM motor control: bare metal (STM32F103C8T6)

Drives a DC motor through an H-bridge using **no libraries**: every peripheral is configured by writing directly to its memory-mapped registers (addresses taken from the STM32F103 reference manual RM0008).

- **Speed** is set by the duty cycle of a 1 kHz PWM signal generated by hardware timer **TIM2, channel 1, on pin PA0**.
- **Direction** is set by two ordinary GPIO pins, **PB12** and **PB13**, driven with the atomic `BSRR` register.
- The main loop ramps the motor up, holds, ramps down, stops briefly, then repeats in the opposite direction.

## Wiring

| Blue Pill pin | Role | Connects to (typical H-bridge board) |
|---|---|---|
| PA0 | TIM2_CH1 PWM output | Enable / PWM input (e.g. `ENA` on an L298N) |
| PB12 | Direction bit A | `IN1` |
| PB13 | Direction bit B | `IN2` |
| GND | Common ground | Driver GND (must be shared with the motor supply) |

> The code does not depend on a specific driver. If your H-bridge labels its pins differently, only this table changes.

Direction truth table (as used in `main.c`):

| PB12 | PB13 | Result |
|---|---|---|
| 1 | 0 | Forward |
| 0 | 1 | Reverse |
| 0 | 0 | Stop (coast) |

## Build and flash

```
make            # arm-none-eabi-gcc -> firmware.elf -> firmware.bin
make stmflash   # st-flash write firmware.bin 0x8000000
make clean
```

# Register reference

The STM32F103 is a memory-mapped microcontroller: each peripheral has a **base address**, and each of its registers sits at a fixed **offset** from it. `main.c` defines each register as a `volatile uint32_t` at that address, so reading or writing the variable reads or writes the hardware. `volatile` stops the compiler from optimizing the accesses away.

## Summary table

| Register | Address | Peripheral | One-line purpose |
|---|---|---|---|
| `RCC_APB1ENR` | `0x4002 101C` | RCC | Turn on the clock of APB1 peripherals (TIM2) |
| `RCC_APB2ENR` | `0x4002 1018` | RCC | Turn on the clock of APB2 peripherals (GPIOA, GPIOB) |
| `GPIOA_CRL` | `0x4001 0800` | GPIOA | Configure the mode of pins PA0 to PA7 |
| `GPIOB_CRH` | `0x4001 0C04` | GPIOB | Configure the mode of pins PB8 to PB15 |
| `GPIOB_BSRR` | `0x4001 0C10` | GPIOB | Atomically set or clear individual output pins |
| `TIM2_CR1` | `0x4000 0000` | TIM2 | Timer control: start/stop, preload behaviour |
| `TIM2_EGR` | `0x4000 0014` | TIM2 | Software-generated events (update event) |
| `TIM2_CCMR1` | `0x4000 0018` | TIM2 | Channel 1 mode (PWM mode 1) and preload |
| `TIM2_CCER` | `0x4000 0020` | TIM2 | Enable the channel 1 output and set its polarity |
| `TIM2_PSC` | `0x4000 0028` | TIM2 | Prescaler: divides the timer clock |
| `TIM2_ARR` | `0x4000 002C` | TIM2 | Auto-reload: sets the PWM period |
| `TIM2_CCR1` | `0x4000 0034` | TIM2 | Compare value: sets the PWM duty cycle |

## 1. Clock enable registers (RCC)

On this MCU a peripheral is **powered down (clock gated) after reset**. Until its clock is enabled, writes to its registers are ignored and reads return 0. Enabling clocks is therefore always the first step.

### `RCC_APB1ENR`: APB1 peripheral clock enable

TIM2 sits on the APB1 bus.

| Bit | Name | Value used | Meaning |
|---|---|---|---|
| 0 | `TIM2EN` | 1 | Enables the clock of timer TIM2 |

```c
RCC_APB1ENR |= (1 << 0);
```

### `RCC_APB2ENR`: APB2 peripheral clock enable

GPIO ports sit on the APB2 bus.

| Bit | Name | Value used | Meaning |
|---|---|---|---|
| 2 | `IOPAEN` | 1 | Enables the clock of GPIOA (pin PA0 = PWM output) |
| 3 | `IOPBEN` | 1 | Enables the clock of GPIOB (pins PB12, PB13 = direction) |

```c
RCC_APB2ENR |= (1 << 2) | (1 << 3);
```

`|=` is used so that other peripherals' enable bits are left untouched.

> `AFIOEN` (bit 0) is **not** needed: TIM2_CH1 is on PA0 by default, and the alternate-function I/O block is only required to *remap* pins or configure external interrupts.

## 2. GPIO configuration registers (`CRL` / `CRH`)

Each GPIO pin is configured by a **4-bit field**: `CNF[1:0]` (bits 3:2) followed by `MODE[1:0]` (bits 1:0).

- `CRL` ("low") holds pins 0 to 7, so pin *n* uses bits `[4n+3 : 4n]`.
- `CRH` ("high") holds pins 8 to 15, so pin *n* uses bits `[4(n-8)+3 : 4(n-8)]`.

**MODE bits** (output mode and slew rate)

| MODE[1:0] | Meaning |
|---|---|
| 00 | Input |
| 01 | Output, max speed 10 MHz |
| 10 | Output, max speed 2 MHz |
| 11 | Output, max speed 50 MHz |

**CNF bits when MODE is an output**

| CNF[1:0] | Meaning |
|---|---|
| 00 | General-purpose push-pull (pin driven by software via `ODR`/`BSRR`) |
| 01 | General-purpose open-drain |
| 10 | **Alternate-function** push-pull (pin driven by a peripheral, e.g. a timer) |
| 11 | Alternate-function open-drain |

After reset every pin is **floating input** (field = `0100`), so each field is first **cleared** (`&= ~(0xF << shift)`) and then **set** (`|= value << shift`). Clearing first matters because `|=` alone could leave stale bits from the reset value.

### `GPIOA_CRL`: configures PA0

| Field | Bits | Value | Decoded |
|---|---|---|---|
| PA0 | 3:0 | `0x9` = `1001` | CNF=`10` (alternate-function push-pull), MODE=`01` (output, 10 MHz) |

```c
GPIOA_CRL &= ~(0xF << 0);
GPIOA_CRL |=  (0x9 << (0 * 4));
```

**Why alternate-function?** PA0 must be driven by the *timer*, not by the GPIO output data register. "Alternate function" connects the pin to the peripheral's output (here TIM2_CH1). Plain general-purpose output would ignore the PWM entirely.

### `GPIOB_CRH`: configures PB12 and PB13

| Field | Bits | Value | Decoded |
|---|---|---|---|
| PB12 | 19:16 | `0x1` = `0001` | CNF=`00` (general-purpose push-pull), MODE=`01` (10 MHz) |
| PB13 | 23:20 | `0x1` = `0001` | CNF=`00` (general-purpose push-pull), MODE=`01` (10 MHz) |

```c
GPIOB_CRH &= ~(0xF << 16);   GPIOB_CRH |= (0x1 << 16);   // PB12
GPIOB_CRH &= ~(0xF << 20);   GPIOB_CRH |= (0x1 << 20);   // PB13
```

These two pins are **normal software-controlled outputs** (the direction bits), so they use CNF=`00`, not alternate-function.

---

## 3. `GPIOB_BSRR`: bit set/reset register

Writing to a pin's output data register (`ODR`) with `|=` / `&=` is a read-modify-write that an interrupt could corrupt. `BSRR` avoids this: it is **write-only**, and a single write changes only the pins whose bits you set, atomically.

| Bits | Name | Effect of writing 1 |
|---|---|---|
| 15:0 | `BSy` | **Set** pin *y* (output high) |
| 31:16 | `BRy` | **Reset** pin *y* (output low) |

Writing 0 to any bit has no effect. If the same pin has both a set and a reset bit, *set* wins.

Macros used in the code:

| Macro | Value | Meaning |
|---|---|---|
| `GPIOB_BSRR_BS12` | `1u << 12` | PB12 high |
| `GPIOB_BSRR_BR12` | `1u << 28` (16 + 12) | PB12 low |
| `GPIOB_BSRR_BS13` | `1u << 13` | PB13 high |
| `GPIOB_BSRR_BR13` | `1u << 29` (16 + 13) | PB13 low |

Usage (both pins change in the same write, so they never pass through an unintended state):

```c
GPIOB_BSRR = BS12 | BR13;   // forward : PB12=1, PB13=0
GPIOB_BSRR = BR12 | BS13;   // reverse : PB12=0, PB13=1
GPIOB_BSRR = BR12 | BR13;   // stop    : PB12=0, PB13=0
```

## 4. TIM2: the PWM generator

TIM2 is a 16-bit general-purpose timer. It contains a counter `CNT` that counts up from 0 to `ARR`, then wraps to 0 (an **update event**). In PWM mode 1 the output is **high while `CNT < CCR1`** and low otherwise, which produces a square wave whose frequency is set by `PSC` and `ARR`, and whose duty cycle is set by `CCR1`.

```
CNT:  0 ............ CCR1 ............ ARR | 0 ...
OUT:  ‾‾‾‾‾‾‾‾‾‾‾‾‾‾|__________________|  ‾‾‾‾‾
      ^ high (CNT < CCR1)  ^ low           ^ next period
```

### `TIM2_PSC`: prescaler

Divides the timer input clock: `f_counter = f_timer / (PSC + 1)`.

```c
TIM2_PSC = 7;   // divide by 8
```

The code never configures the RCC clock tree, so after reset the system runs from the internal **8 MHz HSI**, and TIM2 gets 8 MHz. With `PSC = 7` the counter ticks at 8 MHz / 8 = **1 MHz** (1 µs per tick).

### `TIM2_ARR`: auto-reload register

The value the counter counts up to before wrapping, so the period is `ARR + 1` ticks.

```c
TIM2_ARR = 1000 - 1;   // 999
```

`1000` ticks × 1 µs = 1 ms, which gives a **1 kHz PWM frequency**:

```
f_PWM = f_timer / ((PSC + 1) × (ARR + 1)) = 8 MHz / (8 × 1000) = 1 kHz
```

`ARR` also defines the duty-cycle **resolution**: duty can be set in 1000 steps (0.1 % each).

### `TIM2_CR1`: control register 1

| Bit | Name | Value used | Meaning |
|---|---|---|---|
| 0 | `CEN` | set at the very end | Counter enable: starts the timer |
| 7 | `ARPE` | 1 | Auto-reload preload enable: writes to `ARR` are buffered and take effect at the next update event instead of immediately |

```c
TIM2_CR1 = (1 << 7);    // configuration: ARPE on
...
TIM2_CR1 |= (1u << 0);  // last step: CEN = 1, timer starts
```

The first line uses `=` (not `|=`), which also forces the other bits to their defaults: edge-aligned counting, **up-counting** (`DIR = 0`) and the counter not yet running. The timer is started only after everything else is configured.

### `TIM2_CCMR1`: capture/compare mode register 1

Controls how channels 1 and 2 behave. Only the **channel 1** half (the low byte) is used here.

| Bits | Name | Value used | Meaning |
|---|---|---|---|
| 1:0 | `CC1S` | `00` | Channel 1 is configured as an **output** (compare), not an input capture |
| 3 | `OC1PE` | 1 | Output-compare **preload enable**: writes to `CCR1` are buffered and applied at the next update event |
| 6:4 | `OC1M` | `110` | **PWM mode 1**: active (high) while `CNT < CCR1`, inactive afterwards |

```c
TIM2_CCMR1 &= ~((3u << 0) | (7u << 4));   // clear CC1S and OC1M
TIM2_CCMR1 |=  (6u << 4) | (1u << 3);     // OC1M = 110, OC1PE = 1
```

(`OC1M = 111` would be PWM mode 2, the inverse behaviour.)

**Why preload matters:** the main loop changes `CCR1` constantly while the timer runs. Without `OC1PE`, a new value could take effect in the middle of a period and cause a glitch (a pulse that is too short or too long). With preload, each new duty value waits for the period boundary, so every PWM cycle is clean.

### `TIM2_CCR1`: capture/compare register 1

The compare value that sets the duty cycle:

```
duty (%) = CCR1 / (ARR + 1) × 100
```

| `CCR1` | Duty |
|---|---|
| 0 | 0 % (output always low: motor off) |
| 500 | 50 % |
| 999 | 99.9 % (maximum reachable here) |

```c
TIM2_CCR1 = 0;                       // start at 0 %
for (d = 0; d <= 999; d++) TIM2_CCR1 = d;   // ramp up
```

To get a true 100 %, `CCR1` must be greater than `ARR` (e.g. 1000).

### `TIM2_CCER`: capture/compare enable register

| Bit | Name | Value used | Meaning |
|---|---|---|---|
| 0 | `CC1E` | 1 | Connects the channel 1 output to the pin (PA0). **Without this the PWM runs internally but never appears on the pin** |
| 1 | `CC1P` | 0 | Polarity: 0 = active-high (pin is high during the "on" part of the period) |

```c
TIM2_CCER &= ~(1u << 1);   // CC1P = 0, active high
TIM2_CCER |=  (1u << 0);   // CC1E = 1, output enabled
```

### `TIM2_EGR`: event generation register

Lets software trigger events by hand.

| Bit | Name | Value used | Meaning |
|---|---|---|---|
| 0 | `UG` | 1 | Generate an **update event**: resets the counter and **copies the preload (shadow) registers into the active ones** |

```c
TIM2_EGR |= (1u << 0);
```

**Why this is necessary:** `PSC`, `ARR` (with `ARPE`) and `CCR1` (with `OC1PE`) are all *buffered*. Their new values would normally only become active at the **first natural overflow**, and until then the timer would run with the reset values (`PSC = 0`, `ARR = 0`). Forcing one update event right after configuration loads everything immediately, so the very first PWM period is already correct.

(`EGR` is write-only; its bits always read 0, so `|=` and `=` behave the same.)

## Initialization order (and why)

1. **Enable clocks**: TIM2, GPIOA, GPIOB (nothing works before this).
2. **Configure pins**: PA0 as alternate-function output, PB12/PB13 as outputs.
3. **Configure the timebase**: `CR1` (preload), `ARR`, `PSC`.
4. **Configure channel 1**: `CCMR1` (PWM mode 1 + preload), `CCR1 = 0` (start with the motor off), `CCER` (polarity + output enable).
5. **Load the buffers**: `EGR.UG = 1` forces `PSC`/`ARR`/`CCR1` into the active registers.
6. **Start the timer**: `CR1.CEN = 1`.

Starting with `CCR1 = 0` and enabling the counter last guarantees the motor does not twitch at power-up.

## Main loop

```
direction pins -> forward
ramp  CCR1: 0 -> 999   (accelerate)
hold at full duty
ramp  CCR1: 999 -> 0   (decelerate)
both direction pins low   (pause before reversing)
direction pins -> reverse
ramp up, hold, ramp down
both direction pins low   (pause)
repeat
```

The ramps and pauses use a software `delay()` (a `nop` loop), so their real length depends on the clock speed and compiler optimization level. The pause with both inputs low before each reversal protects the driver and motor from the current spike of an abrupt direction change.

## Things to try next

- **Higher PWM frequency.** 1 kHz is often audible as a motor whine. At 8 MHz, `PSC = 0` and `ARR = 399` gives 20 kHz with 400 duty steps.
- **Change the system clock.** If the PLL is configured for 72 MHz, `PSC` and `ARR` must be recalculated from the new timer clock (on this chip, TIM2 runs at 2× the APB1 clock when APB1 is divided by 2).
- **Use the CMSIS device header** (`stm32f103xb.h`) instead of hand-typed addresses and bit numbers: the same register names with named bit masks (`TIM_CR1_CEN`, `RCC_APB2ENR_IOPAEN`, ...).
- **Replace the `nop` delays with the SysTick timer**, for predictable timing.
- Compare with the [`../HAL/`](../HAL/) version to see which of these registers HAL's `HAL_TIM_PWM_Start()` and `__HAL_TIM_SET_COMPARE()` are writing for you.
